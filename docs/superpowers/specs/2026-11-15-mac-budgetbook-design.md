## 1. 의도와 배경

Windows용 가계부(WPF, 명세서 참고)를 **Mac에서 쓰기 위해 새로 만든다.** 이번 작업의 핵심 동기는 **디자인 개선**이다 [사용자 결정].

기능은 지금 앱과 같게 가져가되, 명세서 7장에서 찾은 버그와 불편 사항을 고친다. 계산 규칙(회계기간, 정렬, 합계)은 원본과 똑같이 동작해야 한다.

## 2. 목표 · 비목표 · 반목표

**목표**
1. 명세서 4장의 기능을 모두 Mac 앱으로 제공한다. 달력, 일별 지출, 무지출 데이, 월간 요약, 카테고리 메모, 고정 지출, 회계기간 설정, 카테고리 관리가 포함된다.
2. 새 화면 구조와 테마 3종을 적용하고, 다크 모드를 지원한다(§6).
3. 명세서 7장의 버그를 고친다. 특히 데이터 유실(ISSUE-05), 카테고리 번호 재사용(ISSUE-03), 오늘이 안 보이는 회계월(ISSUE-01)은 반드시 고친다.
4. Windows 버전 데이터(`data.json`)를 가져올 수 있게 한다.

**비목표 (이번 범위 아님)**
- 수입 관리, 예산, 통계 차트, 검색
- 기기 간 동기화, iPhone·iPad 앱, App Store 배포
- Windows용 배포. 코드는 Windows에서도 개발·실행되지만 배포 대상은 Mac뿐이다.

**반목표 (기능이 돌아가도 이러면 실패)**
- 데이터가 조용히 사라지거나, 저장 실패를 사용자가 모르는 상태
- 회계기간·합계 계산 결과가 원본과 달라지는 것. 명세서 §4.1 표와 하나라도 다르면 실패다.
- Electron급으로 무거운 앱(수백 MB, 높은 메모리 사용)

## 3. 제약

| 제약 | 내용 |
|---|---|
| 개발 환경 | 현재 개발 PC는 Windows 11이다. Tauri 앱은 Windows에서 개발·실행하며 확인할 수 있다. |
| Mac 빌드 | Mac용 `.app`·`.dmg`는 macOS에서만 빌드된다(Tauri는 크로스 컴파일 불가). **사용자의 Mac에서 직접 빌드·확인한다** [사용자 결정]. 코드를 Mac으로 옮기는 방법(원격 저장소, 압축 파일 등)은 사용자가 정하며, 원격 저장소를 만들거나 push하는 일은 사용자가 요청할 때만 한다. |
| 대상 Mac | **Apple Silicon, macOS 15(Sequoia) 이상** [사용자 결정]. 빌드 대상은 `aarch64-apple-darwin` 하나, `minimumSystemVersion`은 `15.0`이다. 화면 기술은 Safari 18 기준 기능까지 쓸 수 있다. 개발 중에는 Windows의 WebView2(Chromium)로 확인하므로 Chromium 전용 기능은 쓰지 않는다. |
| 배포 | **본인만 사용** [사용자 결정]. Developer ID 서명·공증 없이 Mac에서 직접 빌드한다(로컬 빌드 앱은 그대로 실행된다). |
| 시간대 | 모든 날짜 판단은 **한국시간(Asia/Seoul)** 기준이다. Mac 시간대 설정과 무관하다 [사용자 결정]. |
| 금액 | 원 단위 정수만 받는다 [제 결정]. 0 이상, 최대 999억 9999만 9999원. |
| 네트워크 | 없음. 완전 오프라인 앱이다. |
| 사용자 | 한 사람이 한 Mac에서 쓴다. 다중 사용자나 동시 접근은 고려하지 않는다. |
| 개발 도구 | Windows 개발 PC에 Rust 툴체인과 MSVC 빌드 도구가 필요하다. WebView2는 Windows 11에 기본으로 들어 있다. |

## 4. 접근 방식

### 4.1 기술 스택

| | Tauri 2 + Vue 3 + TypeScript (선택) | Swift (SwiftUI) | Electron + Vue |
|---|---|---|---|
| 결과물 | Mac 앱 약 10MB, OS 내장 웹 엔진 사용 | 가장 Mac다운 앱 | 100MB 이상, Chromium 내장 |
| 개발 환경 | Windows에서 개발·확인 가능, 최종 빌드만 Mac | 처음부터 Mac + Xcode 필요 | Windows에서 가능 |
| 디자인 자유도 | 높음(CSS). 테마 3종 구현이 쉬움 | Mac 기본 스타일 위주 | 높음 |
| 확장성 | 같은 코드로 Windows 빌드 가능 | iPhone 확장 쉬움, Windows 불가 | Windows 가능 |

**선택: Tauri 2 + Vue 3 + TypeScript** [사용자 결정]
- 지금 Windows PC에서 대부분 개발할 수 있다.
- 디자인 개선과 테마 3종에 CSS가 가장 유리하다.
- Electron보다 훨씬 가볍다.
- Swift는 개발을 Mac에서만 할 수 있어서, Electron은 무거워서 제외했다.

### 4.2 데이터 저장

| | SQLite (선택) | JSON 파일 |
|---|---|---|
| 용량 | 문제없음 | 10년 써도 수 MB라 문제없음 |
| 쓰기 | 바뀐 행만 쓰고, 트랜잭션으로 중간에 꺼져도 안전 | 파일 전체를 매번 다시 씀 |
| 무결성 | 외래키로 고아 데이터를 원천 차단 | 코드로 직접 지켜야 함(원본 버그의 원인) |
| 확장 | 검색·통계를 SQL로 바로 처리 | 코드로 계산 |

**선택: SQLite** [사용자 결정]. JSON은 백업 내보내기와 Windows 데이터 가져오기 용도로만 쓴다.

## 6. 화면 설계

### 6.1 메인 창

```
+----------------------------------------------+---------------------------+
| < 2026년 11월 >  [오늘]                  [설정] | [ 11월 15일 ] [ 11월 요약 ] |
| 지출 51,450  고정 555,000  합계 606,450         +---------------------------+
+----------------------------------------------+ (선택한 탭 내용)            |
|  일    월    화    수    목    금    토        |                           |
|  25    26    27    28    29    30    31        |                           |
|  ...                                           |                           |
|  [15]  칩 칩 +2건                              |                           |
+----------------------------------------------+---------------------------+
```

- **상단 줄:** 회계월 이동(`<` `>`), `[오늘]`, 설정 버튼. 그 아래 요약 한 줄(변동 지출 / 고정 지출 / 합계).
- **달력:** 회계기간 날짜만 그린다(명세서 F-CAL-02와 같음). 행 수는 기간에 맞게 5~6행.
- **오른쪽 패널:** 너비 고정 약 320px, 탭 2개.
- **창:** 최소 크기 1024×700 [제 결정]. 마지막 크기·위치를 기억한다. 실행 시 최대화하지 않는다.

### 6.2 달력 날짜 칸

| 요소 | 동작 |
|---|---|
| 날짜 숫자 | 일요일 빨강, 토요일 파랑(명세서와 같음). 테마에 맞게 색조만 조정한다. |
| 오늘 | 숫자를 강조 원으로 표시한다(한국시간 기준). |
| 선택된 날 | 칸 테두리를 강조한다. |
| 지출 칩 | 카테고리 색 배경에 내용과 금액을 표시한다. 정렬은 명세서 §4.10과 같다. 칸 높이에 들어가는 만큼만 보이고 나머지는 `+N건`으로 줄인다. |
| 칩 글자색 | 배경 밝기에 따라 검정·흰색을 자동으로 고른다(ISSUE-19 해결). |
| 일 합계 | 날짜 숫자와 같은 줄 오른쪽에 `51,450`. 0원이면 표시하지 않는다. 최소 창 크기에서도 칩이 들어가도록 칸 아래쪽이 아니라 숫자 줄에 둔다 [제 결정]. |
| 무지출 | 칩 대신 무지출 도장. 새 디자인에 맞는 도장을 새로 만들고, 원본 이미지는 쓰지 않는다. |
| 클릭 | 그 날짜를 선택하고 오른쪽 패널을 날짜 탭으로 바꾼다. |

### 6.3 오른쪽 패널 — 날짜 탭

탭 이름은 선택한 날짜다(예: `11월 15일`).

```
11월 15일 (일)                [ ] 무지출
-----------------------------------------
o 점심            식비          12,000
o 커피            식비           5,000
o 버스            교통           1,450
-----------------------------------------
내용 [                          ]
금액 [          ]  분류 [식비   v]
                          [ 추가 ]
```

| 기능 | 동작 |
|---|---|
| 목록 | 입력 순서대로. 각 행에 카테고리 색 점, 내용, 카테고리 이름, 금액을 보여준다. |
| 추가 | 내용 → 금액 → 분류 순서로 입력하고 Enter 또는 `추가`. **바로 DB에 저장한다** [제 결정]. 저장 버튼이 없다. 추가 후 내용·금액 칸을 비우고 분류는 유지하며 커서를 내용 칸으로 옮긴다(원본과 같음). |
| 수정 | 항목을 누르면 그 행이 편집 상태가 된다. Enter는 저장, Esc는 취소 [제 결정]. |
| 삭제 | 행의 삭제 버튼, 또는 행 선택 후 `⌫`. 확인창을 띄운 뒤 삭제한다. |
| 금액 입력 | 숫자만 받고, 입력 중에 천 단위 콤마를 자동으로 넣는다. |
| 검증 | 명세서 §6의 문구를 쓰되, 알림창 대신 입력칸 아래에 표시한다 [제 결정]. |
| 무지출 | 지출이 0건일 때만 켤 수 있다. 지출이 있으면 비활성화하고 "지출이 있는 날은 무지출로 표시할 수 없어요"를 안내한다(ISSUE-07 해결, [제 결정]). 무지출인 날에 지출을 추가하면 무지출 표시를 자동으로 해제한다(원본과 같음). 무지출인 날은 목록 대신 상태 문구만 보여준다(ISSUE-08 해결). |

> 원본은 팝업 안에서 복사본을 편집하다가 `저장`을 눌러야 반영됐다. 새 구조는 창 안의 패널이라 동작마다 바로 저장한다. 실행 취소(⌘Z)는 이번 범위에서 제외한다.

### 6.4 오른쪽 패널 — 요약 탭

탭 이름은 회계월이다(예: `11월 요약`).

1. 회계기간 `2026년 10월 25일 ~ 2026년 11월 24일`
2. 카테고리별 합계 목록(명세서 §4.10 순서). 그 회계월에 **지출이 있거나 메모가 있는** 카테고리를 보여준다 [제 결정]. 지출을 다 지워도 메모가 숨지 않게 하기 위해서다. 행을 누르면 그 카테고리의 이번 달 메모 입력칸이 펼쳐지고, 한 번에 하나만 펼쳐진다(명세서 F-MEMO와 같음). 메모는 입력이 멈추고 0.5초 뒤 저장한다(ISSUE-15 해결). 쉬지 않고 입력하는 중에도 1초마다 저장하고, 창을 닫을 때(닫기 버튼·`⌘W`)는 남은 메모를 저장한 뒤 닫는다. 저장이 실패하거나 2초 안에 끝나지 않으면 닫기를 한 번 막고 `메모를 저장하지 못했어요. 한 번 더 닫으면 저장하지 않고 닫아요.`를 알린다. 그 뒤 다시 닫으면 저장을 한 번 더 시도하되 결과와 상관없이 닫는다 [사용자 결정]. `⌘Q`로 끌 때는 마지막 1초 안의 입력을 잃을 수 있다 [사용자 결정]. 단 빈 메모는 0.5초 디바운스로 저장하지 않고, 접을 때·포커스를 잃을 때·달을 바꿀 때·화면이 사라질 때만 저장한다(메모만 있던 행이 입력 중에 사라지는 것을 막기 위해서) [제 결정]. 지출이 없는 카테고리에 새 메모를 쓰는 기능은 원본처럼 두지 않는다(ISSUE-16 유지).
3. 총 지출(변동)
4. 고정 지출 카드. 합계를 보여주고, 누르면 고정 지출 시트(§6.5)가 열린다.
5. 월간 총 지출
6. 무지출 데이 횟수

계산식은 명세서 §4.5와 같다.

### 6.5 고정 지출 시트

메인 창 위에 내려오는 시트다. 명세서 F-FIX의 동작을 따르되 다음을 바꾼다.

| 변경 | 내용 |
|---|---|
| 항목 추가 | 별도 창 대신 시트 안의 입력 줄에서 이름을 넣고 Enter. 중복 이름은 그 자리에서 알린다(ISSUE-14 해결). |
| 지난달 금액 불러오기 | 버튼을 누르면 이번 달 금액이 **빈칸인 항목만** 직전 회계월 금액으로 채운다(ISSUE-11 해결, [제 결정]). 사용자가 직접 `0`을 넣은 항목은 빈칸이 아니므로 덮어쓰지 않는다. 빈칸과 `0`은 구분해서 저장하고 표시한다. |
| 편집 방식 | 시트를 열 때 복사본으로 편집하고 `저장`을 눌러야 반영한다. `취소`·Esc는 모든 변경을 버린다(원본과 같음, 여러 달을 한꺼번에 편집하므로 유지). |
| 시작 회계월 | 메인에서 보고 있는 회계월 |

### 6.6 설정 시트 (`⌘,`, 상단 설정 버튼)

별도 창이 아니라 메인 창 위 시트로 연다 [제 결정]. 창이 둘이면 상태 동기화가 복잡해지기 때문이다.

| 탭 | 내용 |
|---|---|
| 일반 | 회계기간 시작일(1~31일). 고르는 즉시 "이번 회계월: 10/25 ~ 11/24" 미리보기를 보여준다(ISSUE-18). 테마 선택(3종, 미리보기 썸네일). 화면 모드 선택(시스템 따라감 / 라이트 / 다크) |
| 카테고리 | 목록(명세서 §4.10 순서). 선택하면 이름과 색을 **한 곳에서** 편집한다(ISSUE-13 해결). 추가 영역은 이름, 프리셋 8종, HEX 입력, 팔레트 48색(명세서 F-CAT과 같은 색). HEX는 `#` 없이 입력해도 미리보기에 바로 반영한다(ISSUE-21 해결). |
| 데이터 | Windows 데이터 가져오기, JSON으로 내보내기, 백업 폴더 열기. 가져오기는 DB가 비어 있는 첫 실행 직후에도 항상 확인 창을 거친 뒤 기존 데이터를 바꾼다 [제 결정] |

**카테고리 삭제** [제 결정]
- 지출도 메모도 없는 카테고리는 확인 후 삭제한다.
- 지출은 없고 메모만 있는 카테고리는 "메모 N개도 함께 삭제됩니다" 확인 후 메모와 함께 삭제한다.
- 지출이 있는 카테고리는 "이 카테고리의 지출 N건을 옮길 카테고리"를 고르게 하고, 옮긴 뒤 삭제한다. 고아 데이터가 생기지 않는다(ISSUE-04 해결).
  - 메모도 함께 옮긴다. 옮길 카테고리에 같은 달 메모가 이미 있으면 줄바꿈으로 이어 붙인다.
  - 지출 이동, 메모 병합, 카테고리 삭제는 하나의 트랜잭션이다.
- 고정 지출 항목은 카테고리와 연결되지 않으므로 삭제 판단과 무관하다.

**색 프리셋 조정** [제 결정]: 정렬 알고리즘(명세서 §4.10)은 그대로 두고, '주황'과 '초록' 프리셋 HEX만 이름과 같은 계열에 들어가도록 바꾼다(ISSUE-20). 새 값은 빌더가 정하되, §4.10 판정 결과가 각각 주황(1)·초록(3)이어야 한다.

**설정 변경 후 달력** [제 결정]: 시작일이 실제로 바뀌었을 때만 오늘이 속한 회계월로 이동한다. 그 밖에는 보던 달을 유지한다(ISSUE-02 해결).

### 6.9 시작 상태

- **실행 시:** 한국시간 오늘이 속한 회계기간을 연다(ISSUE-01 해결). 오늘을 선택하고 날짜 탭을 연다 [제 결정].

## 8. 데이터 설계

### 8.1 위치와 설정

- **DB:** `~/Library/Application Support/<번들 ID>/budgetbook.db`
- **접근:** 데이터 계층은 **Rust**(`rusqlite`, SQLite 내장 빌드)로 작성하고, 작업 단위의 Tauri 커맨드로 TypeScript에 노출한다 [제 결정].
  - 예: `add_expense`, `update_expense`, `delete_expense`, `set_no_expense_day`, `delete_category_with_move`, `save_fixed_expenses`, `import_replace_all`, `restore_backup`
  - 각 커맨드는 하나의 트랜잭션 안에서 실행한다.
  - 연결은 앱 전체에서 하나만 쓴다(`Mutex<Connection>`).
- **이유:** 공식 `tauri-plugin-sql`은 연결 풀을 써서, TypeScript에서 보낸 `BEGIN`·`COMMIT`이 서로 다른 연결에서 실행될 수 있다. 여러 단계 저장(지출 추가 + 무지출 해제, 카테고리 삭제 + 지출 이동, 가져오기 전체 교체)을 원자적으로 보장할 수 없다.
- **역할 분담:** Rust는 저장소 역할만 한다. 회계기간 계산·정렬·집계 같은 비즈니스 규칙은 TypeScript(`src/domain`)에 둔다. 예를 들어 화면이 기간(시작일~종료일)을 계산해 넘기면, Rust는 그 범위의 데이터를 돌려준다.
- **연결 설정:** `PRAGMA foreign_keys = ON`, `journal_mode = WAL`
- **마이그레이션:** SQL 파일을 바이너리에 포함하고 `PRAGMA user_version`으로 버전을 관리한다.

### 8.2 스키마

```sql
CREATE TABLE categories (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,   -- 삭제된 ID 재사용 안 함 (ISSUE-03)
  name        TEXT NOT NULL UNIQUE COLLATE NOCASE,
  color       TEXT NOT NULL,                       -- '#RRGGBB' 대문자
  created_at  TEXT NOT NULL,                       -- ISO 8601, +09:00
  updated_at  TEXT NOT NULL
);

CREATE TABLE expenses (
  id          TEXT PRIMARY KEY,                    -- UUID
  date        TEXT NOT NULL,                       -- 'YYYY-MM-DD' (KST)
  description TEXT NOT NULL CHECK (length(trim(description)) > 0),
  amount      INTEGER NOT NULL CHECK (amount >= 0),
  category_id INTEGER NOT NULL REFERENCES categories(id) ON DELETE RESTRICT,
  created_at  TEXT NOT NULL,
  updated_at  TEXT NOT NULL
);
CREATE INDEX idx_expenses_date ON expenses(date);

CREATE TABLE no_expense_days (
  date        TEXT PRIMARY KEY,                    -- 'YYYY-MM-DD'
  created_at  TEXT NOT NULL
);

CREATE TABLE fixed_expense_items (
  id          TEXT PRIMARY KEY,                    -- UUID
  name        TEXT NOT NULL UNIQUE COLLATE NOCASE,
  sort_order  INTEGER NOT NULL,                    -- 추가 순서
  created_at  TEXT NOT NULL
);

CREATE TABLE fixed_expense_amounts (
  item_id     TEXT NOT NULL REFERENCES fixed_expense_items(id) ON DELETE CASCADE,
  month       TEXT NOT NULL,                       -- 회계월 'YYYY-MM'
  amount      INTEGER NOT NULL CHECK (amount >= 0),
  PRIMARY KEY (item_id, month)
);

CREATE TABLE category_notes (
  month       TEXT NOT NULL,                       -- 회계월 'YYYY-MM'
  category_id INTEGER NOT NULL REFERENCES categories(id) ON DELETE CASCADE,  -- 병합은 삭제 전에 앱이 처리
  note        TEXT NOT NULL,
  updated_at  TEXT NOT NULL,
  PRIMARY KEY (month, category_id)
);

CREATE TABLE settings (
  key         TEXT PRIMARY KEY,                    -- 'accounting_start_day', 'theme' 등
  value       TEXT NOT NULL
);
```

**정해 둔 동작**
- 무지출 표시와 지출은 한 날짜에 함께 있을 수 없다. 앱이 한 트랜잭션 안에서 보장한다. 지출을 추가하면 그 날짜의 `no_expense_days`를 지우고, 무지출은 지출이 0건일 때만 넣는다.
- 고정 지출 금액이 빈칸이면 행이 없다. 사용자가 `0`을 입력하면 금액 0인 행을 저장한다. 합계 계산에서는 둘 다 0이지만, 화면 표시와 '지난달 금액 불러오기'에서는 구분한다.
- 메모가 비면 행을 지운다(원본과 같음).

### 8.3 안전장치 (ISSUE-05, 06 해결)

| 상황 | 동작 |
|---|---|
| DB 열기·마이그레이션 실패 | 오류 화면을 보여준다(다시 시도, 백업에서 복원, 백업 폴더 열기). **기존 파일을 지우거나 새 빈 DB로 덮어쓰지 않는다.** |
| DB 손상 | 기존 DB를 열 때 `PRAGMA quick_check`로 검사하고, 손상이 있으면 열기 실패로 처리해 오류 화면을 보여준다. 일부 페이지만 손상된 DB는 열리기는 해도 조회가 실패하므로, 시작할 때 바로 알리고 복원으로 안내하기 위해서다 [사용자 결정]. |
| 백업에서 복원 | 설정 → 데이터 탭과 오류 화면에서 앱 안에서 복원한다 [제 결정]. 백업 목록(날짜, 지출 건수)에서 하나를 고른다. WAL 모드에서 손으로 파일을 복사하면 남은 `-wal`이 덮어써질 위험이 있어 앱이 처리한다. 동작 순서는 아래와 같다. |
| └ 1. 현재 DB 보관 | 열려 있으면 `VACUUM INTO`로 백업한다. 열 수 없는 상태(오류 화면)이거나 `VACUUM INTO`가 실패하면(DB 일부 손상 등) `budgetbook.db`와 `-wal`·`-shm`을 바이트 그대로 `backups/unopenable-YYYYMMDD-HHMMSS.db`(+`-wal`·`-shm`)로 복사한다. 열린 연결이 있으면 닫기 전에 복사한다(닫을 때 WAL이 원본에 합쳐져 원본이 바뀌지 않게) [사용자 결정]. 같은 초에 겹치면 `-1`, `-2`를 붙인다. 이 파일은 백업 목록에 나오지 않고 자동 정리에서도 지워지지 않는다. 두 방법이 모두 실패하면 복원을 중단한다. |
| └ 2. 백업 검증 | 고른 백업을 같은 폴더의 임시 파일로 복사한 뒤 읽기 전용으로 열어, 스키마 버전과 지출 테이블을 읽을 수 있는지 확인한다. 손상됐거나 빈 파일이면 임시 파일을 지우고 원래 DB를 다시 연 뒤 오류를 알린다. |
| └ 3. 교체 | 연결을 닫고 `-wal`·`-shm`을 지운 뒤 임시 파일을 DB 경로로 rename해 한 번에 교체하고 다시 연다. 복사 단계에서 실패하면 원래 DB를 다시 연다. |
| 쓰기 실패 | 화면에 오류를 알리고, 입력한 값은 입력칸에 남겨 다시 시도할 수 있게 한다. |
| 자동 백업 | 하루 첫 실행 때 `VACUUM INTO`로 `backups/budgetbook-YYYYMMDD-HHMMSS.db`(한국시간)를 만든다. 같은 초에 겹치면 `-1`, `-2`를 붙인다. 이 이름 형식의 파일만 최근 14개를 보관한다 [제 결정]. 앱을 켜 둔 채 한국시간 날짜가 바뀌면, 앱이 날짜 변경을 알아챈 때 그날 백업이 없으면 만든다 [사용자 결정]. |
| 자동 백업 실패 | 시작할 때나 날짜가 바뀔 때 자동 백업을 만들지 못하면 화면에 알린다. 앱 사용은 막지 않는다 [사용자 결정]. |
| 가져오기·전체 교체 전 | 자동 백업을 한 번 더 만든다. |

### 8.4 Windows 데이터 가져오기

명세서 §8.4의 대응표를 따른다. 추가로 다음을 정한다.

- **대상:** 항상 "기존 데이터를 모두 지우고 가져오기"로 동작하며, 첫 실행 직후(DB가 비어 있을 때)에도 확인 창을 거친다 [제 결정]. 가져오기 전에 백업한다. 합치기(병합)는 지원하지 않는다 [제 결정].
- **카테고리:** 기본 카테고리는 지우고 원본 카테고리로 바꾼다. 새 ID를 받고 원본 ID와의 대응표로 지출과 메모를 연결한다.
- **원본 오류 데이터:** 카테고리를 찾을 수 없는 지출이 있으면 `미분류`(회색) 카테고리를 만들어 넣는다.
- **변환:**
  - `IsNoExpenseDay=true` 행은 `no_expense_days`로 옮긴다.
  - `Amount`는 반올림해 정수로 바꾼다.
  - 고정 지출의 `0` 금액은 빈칸(행 없음)으로 가져온다. Windows 버전은 0을 빈칸으로 표시했고, 방문만 한 달도 0으로 저장했기 때문이다.
  - 고정 지출 이름이 겹치면(앞뒤 공백 제거, 대소문자 무시) 뒤 항목을 버리지 않고 이름에 ` (2)`, ` (3)`을 붙여 모두 가져온다. 금액 기록을 잃지 않고 월별 합계를 원본과 같게 하기 위해서다 [사용자 결정].
  - 파일 해석과 변환은 TypeScript(`src/domain`, Vitest로 테스트)에서 하고, 정리된 데이터를 `import_replace_all` 커맨드 하나로 넘겨 트랜잭션으로 저장한다.
  - `Date`는 앞 10자리만 쓴다.
  - `AccountingStartDay`는 settings로 옮긴다.
- **결과 안내:** 가져오기 전에 건수 미리보기(카테고리, 지출, 무지출, 고정 지출, 메모)를, 끝난 뒤 결과를 보여준다.

### 8.5 JSON 내보내기

전체 테이블을 JSON 하나로 내보낸다(형식 버전 포함). 이번 범위에서 이 JSON을 다시 가져오는 기능은 넣지 않는다. 복원은 앱 안의 '백업에서 복원'(§8.3)으로 한다 [제 결정].

- 저장소 위치: 저장소 안 `app/` 폴더에 Tauri 프로젝트를 만든다 [제 결정].
