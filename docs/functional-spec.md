## 1. 제품 개요

달력 중심의 **지출 전용** 개인 가계부. 로컬 PC에서 혼자 쓰는 오프라인 앱이며 모든 데이터는 JSON 파일 하나에 저장된다.

핵심 특징:

1. **사용자 지정 회계기간**: 월급일처럼 매달 시작일(1~31일)을 정하면, 달력과 집계가 그 기간 기준으로 동작한다.
2. **달력에서 바로 입력**: 날짜 칸을 눌러 그날 지출을 여러 건 등록한다. 칸에는 카테고리 색상 칩으로 표시된다.
3. **카테고리 색상 체계**: 카테고리마다 색을 지정하며, 목록은 색 계열(빨강→주황→…→무채색) 순으로 정렬된다.
4. **무지출 데이**: 지출 없는 날을 표시하고 회계월마다 횟수를 센다.
5. **월 고정 지출**: 월세, 통신비 같은 항목을 따로 관리하고 회계월마다 금액을 입력한다.
6. **카테고리별 월 메모**: 회계월마다 카테고리별 메모를 남긴다.

현행에 **없는** 기능: 수입 관리, 예산 설정, 검색, 통계 차트, 내보내기/가져오기, 백업, 다중 사용자, 동기화.

## 2. 용어 정의

| 용어 | 정의 |
|---|---|
| 회계기간 시작일 | 회계기간이 시작되는 날짜(1~31). 기본값 **25**. 종료일은 다음 시작일의 전날로 자동 결정된다. |
| 회계월 | 회계기간 하나를 부르는 이름. "2026년 11월"처럼 연·월로 표기하며 내부 키는 `yyyy-MM`. |
| 회계기간 | 회계월에 속하는 실제 날짜 범위(시작일~종료일). 계산 규칙은 §4.1 참고. |
| 일별 지출(변동 지출) | 특정 날짜에 등록한 지출 한 건. 내용·금액·카테고리로 이루어진다. |
| 고정 지출 | 매달 반복되는 지출 항목. 항목 이름은 모든 달에 공통이고 금액은 회계월마다 따로 입력한다. |
| 무지출 데이 | 지출이 없었다고 표시한 날짜. 일별 지출과 함께 둘 수 없다. |
| 카테고리(분류) | 지출 분류. 이름과 색상을 가진다. |
| 카테고리 메모 | (회계월, 카테고리) 조합마다 하나씩 저장되는 자유 텍스트. |

## 4. 기능 상세

### 4.1 회계기간 계산 (F-PERIOD) — 핵심 비즈니스 규칙

모든 화면(달력, 집계, 무지출 횟수)이 이 규칙을 따른다.

**입력**: 회계월(연, 월), 시작일 `S`(1~31)

**알고리즘**

```
기준월 = 회계월
if S >= 20:            # 20일 이상이면 기간이 전달에서 시작
    기준월 = 회계월 - 1개월
유효시작(연,월) = 연-월-min(S, 그 달의 일수)    # 31일이 없는 달은 말일로 당김
시작일 = 유효시작(기준월)
종료일 = 유효시작(기준월 + 1개월) - 1일
```

- `S >= 20` 이면 회계월 이름은 **종료일이 속한 달**이다. 예: 25일 시작이면 10/25~11/24가 "11월".
- `S < 20` 이면 회계월 이름은 **시작일이 속한 달**이다. 예: 10일 시작이면 11/10~12/9가 "11월".
- 31일이 없는 달은 그 달 말일로 당겨지며, 기간은 빈틈없이 이어진다.

**검증된 예시** (원본 로직을 그대로 옮긴 스크립트로 계산)

| 시작일 | 회계월 | 시작일자 | 종료일자 | 일수 |
|---|---|---|---|---|
| 25 | 2026-11 | 2026-10-25 | 2026-11-24 | 31 |
| 1 | 2026-11 | 2026-11-01 | 2026-11-30 | 30 |
| 10 | 2026-11 | 2026-11-10 | 2026-12-09 | 30 |
| 19 | 2026-11 | 2026-11-19 | 2026-12-18 | 30 |
| 20 | 2026-11 | 2026-10-20 | 2026-11-19 | 31 |
| 31 | 2026-02 | 2026-01-31 | 2026-02-27 | 28 |
| 31 | 2026-03 | 2026-02-28 | 2026-03-30 | 31 |
| 30 | 2028-03 (윤년) | 2028-02-29 | 2028-03-29 | 30 |
| 29 | 2028-03 (윤년) | 2028-02-29 | 2028-03-28 | 29 |

> Mac 버전 구현 시 위 표를 그대로 단위 테스트 케이스로 쓸 수 있다.

**처음 표시할 회계월(현행)**: 실행할 때와 설정 창을 닫을 때 `오늘 날짜의 달력상 연·월`을 회계월로 쓴다. 그래서 오늘이 화면에 안 나오는 경우가 있다(§7 ISSUE-01).

### 4.2 메인 화면 — 달력 (F-CAL)

**구성**
- 상단: `◀` 버튼, 회계월 제목(`2026년 11월`, 월 앞에 0을 붙이지 않음), `▶` 버튼
- 요일 머리글: 일요일(빨강), 월~금(검정), 토요일(파랑). 일요일부터 시작한다.
- 날짜 칸: **6행 × 7열** 고정

| ID | 기능 | 현행 동작 |
|---|---|---|
| F-CAL-01 | 회계월 이동 | `◀`/`▶`로 한 달씩 이동한다. 이동하면 달력을 다시 그리고 월간 지출 패널(§4.5)도 다시 계산한다. |
| F-CAL-02 | 기간 표시 | **현재 회계기간에 속한 날짜만** 칸으로 그린다. 첫 날짜는 그 요일 열에서 시작하고, 기간 밖 날짜(앞뒤 달)는 빈칸으로 둔다. 최대 31일 + 앞쪽 빈칸 6칸 = 37칸이라 6행 안에 들어간다. |
| F-CAL-03 | 날짜 칸 표시 | 왼쪽 위에 일(day) 숫자를 쓴다. 일요일은 빨강, 토요일은 파랑, 나머지는 검정. |
| F-CAL-04 | 지출 칩 | 그날 지출 건마다 카테고리 색 배경의 칩 하나를 그린다. 칩 왼쪽은 내용(넘치면 `…`), 오른쪽은 `12,000원`. 칩 순서는 카테고리 정렬 규칙(§4.10)을 따른다. |
| F-CAL-05 | 일 합계 | 칸 아래에 `합계 N원`을 표시한다. 합계가 0이면 표시하지 않는다. |
| F-CAL-06 | 무지출 표시 | 무지출 데이로 표시된 날은 지출 칩과 합계 대신 "ZERO" 도장 이미지(빨간 원형)를 보여준다. |
| F-CAL-07 | 날짜 칸 클릭 | 칸 어디를 눌러도 그 날짜의 SCR-02가 열린다. 빈칸은 누를 수 없다. |
| F-CAL-08 | 삭제된 카테고리 | 지출의 카테고리를 찾지 못하면 칩 배경을 흰색(`#FFFFFF`)으로 그린다. |

현행에 없는 것: 오늘 날짜 강조, '오늘로 이동' 버튼, 공휴일 표시, 칸이 넘칠 때의 스크롤이나 "+N건 더보기".

### 4.3 일별 지출 편집 (F-DAY) — SCR-02

창 제목 `지출 내역`. 왼쪽은 입력 영역, 오른쪽은 등록 목록이다.

**구성**
- 왼쪽: 날짜 제목(`2026년 11월 15일`), `무지출 Day` 체크박스, `내용` 입력, `금액` 입력, `분류` 선택(카테고리 이름), 버튼 `추가` / `수정 적용` / `저장`
- 오른쪽: `등록된 항목` 목록(각 행: 내용 굵게 + 금액 회색 `N원`), `선택 항목 삭제` 버튼

**편집 모델**: 창을 열 때 그 날짜 데이터의 **복사본**으로 작업한다. `저장`을 눌러야만 반영된다. 창을 닫기(X)로 닫으면 그동안 바꾼 내용은 모두 버려진다.

| ID | 기능 | 현행 동작 |
|---|---|---|
| F-DAY-01 | 초기화 | 기존 항목을 목록에 불러온다. 분류는 첫 번째 카테고리를 미리 선택한다. 무지출 데이인 날이면 체크박스를 켜고 입력 칸을 비활성화한다. |
| F-DAY-02 | 추가 | 검증(아래)을 통과하면 새 항목을 목록 끝에 붙인다. 그 뒤 내용·금액 칸을 비우고 분류는 그대로 두며 커서를 `내용`으로 옮긴다. 목록에 무지출 표식이 있으면 지운다. |
| F-DAY-03 | 항목 선택 → 편집 | 목록에서 항목을 고르면 입력 칸에 그 값이 채워진다. 금액은 콤마 없이 `0.##` 형식이다. 무지출 표식을 고르면 편집 대상이 없는 상태가 된다. |
| F-DAY-04 | 수정 적용 | 선택한 항목의 내용·금액·분류를 입력값으로 바꾼다. 그 뒤 입력 칸을 비우고 선택을 해제한다. 선택된 항목이 없으면 오류 메시지를 띄운다. |
| F-DAY-05 | 선택 항목 삭제 | 확인창 `선택한 항목을 삭제하시겠습니까?`(예/아니오) 후 목록에서 지운다. 지운 것이 무지출 표식이면 체크를 풀고 입력 칸을 활성화한다. |
| F-DAY-06 | 무지출 Day 체크 | **확인 없이 목록을 비우고** 무지출 표식 1건으로 바꾼다. 내용·금액·분류·`추가`는 비활성화된다. |
| F-DAY-07 | 무지출 Day 해제 | 목록을 모두 비우고 입력 칸을 활성화하며 첫 카테고리를 선택한다. |
| F-DAY-08 | 저장 | 체크가 켜져 있으면 목록을 무지출 표식 1건으로 정리하고, 꺼져 있으면 무지출 표식을 지운다. 그 결과로 그 날짜 데이터를 **통째로 교체**하고 파일에 저장한 뒤 창을 닫는다. 남은 항목이 0건이면 그 날짜 데이터 자체를 지운다. 저장 후 달력과 월간 지출 패널을 다시 그린다. |

**입력 검증**

| 필드 | 규칙 | 위반 시 메시지 |
|---|---|---|
| 내용 | 앞뒤 공백 제거 후 비어 있으면 안 됨 | `내용을 입력해주세요.` |
| 금액(추가) | 숫자여야 함. 천 단위 콤마, 소수점, 앞뒤 공백 허용 | `금액을 올바르게 입력해주세요.` |
| 금액(추가) | 0 이상 (0원 허용) | `금액은 0 이상으로 입력해주세요.` |
| 금액(수정) | 숫자이면서 0 이상 | `금액을 0 이상의 숫자로 입력해주세요.` |
| 분류 | 선택 필수 | `분류를 선택해주세요.` |

- 금액은 소수를 받아들이지만 표시할 때는 정수로 반올림한다(`N0` 형식).
- 분류 목록은 저장된 카테고리 순서(설정에서 정렬된 순서)를 따른다. 등록 목록은 입력 순서이며 카테고리는 표시하지 않는다.

### 4.4 무지출 데이 (F-ZERO)

| ID | 규칙 |
|---|---|
| F-ZERO-01 | 무지출 데이는 내부적으로 `IsNoExpenseDay = true`, 금액 0, 카테고리 0, 내용 빈 문자열인 특수 항목 1건으로 저장한다. |
| F-ZERO-02 | 한 날짜에 무지출 표식과 일반 지출은 함께 있을 수 없다(SCR-02에서 강제). |
| F-ZERO-03 | 달력 칸은 무지출 이미지로 표시한다(F-CAL-06). |
| F-ZERO-04 | 현재 회계기간에서 무지출 표식이 있는 **날짜 수**를 세어 `무지출 데이 N회`로 보여준다. |
| F-ZERO-05 | 무지출 표식은 지출 합계와 카테고리 집계에서 빠진다. |

### 4.5 월간 지출 패널 (F-SUM) — SCR-01 오른쪽(폭 300)

위에서부터 다음 순서로 표시한다.

| 순서 | 요소 | 현행 동작 |
|---|---|---|
| 1 | `설정` 버튼 | SCR-03을 연다. |
| 2 | 제목 `월간 지출` | 고정 텍스트 |
| 3 | 기간 | `2026년 10월 25일 ~ 2026년 11월 24일` (회색) |
| 4 | 카테고리별 합계 목록 | 현재 회계기간 안의 일별 지출을 카테고리별로 더한다. 각 행은 색 사각형 + 카테고리 이름 + `N원`(굵게). 정렬은 §4.10. 카테고리를 찾지 못하면 이름은 `미분류`, 색은 흰색. 지출이 없으면 `지출 내역이 없습니다.`를 표시한다. |
| 5 | 총 지출 | `총 지출 N원` = 4번 합계의 총합(변동 지출만) |
| 6 | 월간 고정 지출 카드(버튼) | 제목 `월간 고정 지출`, 금액 `합계 N원`(주황). 현재 회계월(`yyyy-MM`) 키의 고정 지출 금액 합계. 누르면 SCR-04가 현재 회계월로 열린다. |
| 7 | 월간 총 지출 | `월간 총 지출 N원` = 총 지출 + 고정 지출 합계 (주황, 강조 배경) |
| 8 | 무지출 데이 | `무지출 데이 N회` (오른쪽 정렬) |

**다시 계산하는 시점**: 앱 시작, 회계월 이동, SCR-02 저장, SCR-04 `저장 및 닫기`, SCR-03이 닫힐 때.

**집계 공식**

```
카테고리합계[c] = Σ 금액 (날짜 ∈ [시작일, 종료일], IsNoExpenseDay = false, 카테고리 = c)
총지출         = Σ 카테고리합계
고정지출합계    = Σ 고정지출항목.월별금액["yyyy-MM"] (해당 키가 없으면 0)
월간총지출      = 총지출 + 고정지출합계
무지출횟수      = |{ 날짜 ∈ 기간 : 그 날짜에 무지출 표식 존재 }|
```

### 4.7 고정 지출 (F-FIX) — SCR-04, SCR-05

**데이터 개념**: 고정 지출 **항목**(이름)은 모든 달에 공통이고, **금액**은 회계월 키(`yyyy-MM`)마다 따로 저장한다. 전달 금액을 자동으로 가져오지 않는다.

**SCR-04 구성**: 제목 `고정 지출 관리`, `이전 달` / 회계월 표시(`2026년 11월`) / `다음 달`, 항목 목록(이름 | 금액 입력 칸 | `삭제`), `이번 달 고정 지출 합계 N원`, `+ 항목 추가`, `저장 및 닫기`

**편집 모델**: 창을 열 때 불러온 복사본으로 작업한다. `저장 및 닫기`를 눌러야 파일에 저장된다. 창을 닫기(X)로 닫으면 **항목 추가·삭제와 모든 달의 금액 변경이 버려진다.**

| ID | 기능 | 현행 동작 |
|---|---|---|
| F-FIX-01 | 열기 | 메인 달력의 현재 회계월로 연다. 이 창에서 달을 옮겨도 메인 달력은 바뀌지 않는다. |
| F-FIX-02 | 금액 표시 | 그 회계월 금액을 보여준다. 0이거나 값이 없으면 빈칸이다. 입력 칸 툴팁: `이 회계월의 금액을 입력하세요.` |
| F-FIX-03 | 합계 미리보기 | 금액 칸을 고칠 때마다 합계를 다시 계산한다. 숫자가 아니거나 0 이하인 칸은 빼고 더한다. |
| F-FIX-04 | 달 이동 | 현재 달 금액을 먼저 검증해 메모리에 반영한다. 실패하면 이동하지 않는다. |
| F-FIX-05 | 항목 추가 | 현재 달 금액을 검증·반영한 뒤 SCR-05를 연다. 이름을 받으면 목록 **끝**에 추가하고 금액은 비워 둔다. 같은 이름이 있으면(대소문자 무시) `이미 등록된 항목 이름입니다.`를 띄우며, 이때 SCR-05는 이미 닫혀 있다. |
| F-FIX-06 | 항목 삭제 | 현재 달 금액을 검증·반영한 뒤 확인창 `'{이름}' 항목을 삭제할까요? 저장된 모든 월의 금액도 함께 삭제됩니다.`(예/아니오)을 띄운다. 예를 누르면 항목과 모든 달의 금액을 지운다. |
| F-FIX-07 | 저장 및 닫기 | 현재 달 금액을 검증·반영한 뒤 전체를 파일에 저장하고 창을 닫는다. 메인 패널을 다시 계산한다. |

**금액 검증**: 콤마를 지우고 앞뒤 공백을 자른다. 빈칸은 0으로 저장한다. 숫자가 아니거나 음수이면 `'{이름}'의 금액을 올바르게 입력하세요. (0 이상의 숫자)` 메시지를 띄우고 그 칸에 포커스를 둔다. 금액을 입력한 적 없는 달은 키가 없는 상태로 남고, 방문만 한 달은 0으로 저장될 수 있다.

**SCR-05 (고정 지출 항목 추가)**: 안내 `고정 지출 항목 이름을 입력하세요.`, 이름 입력 칸(열리면 자동 포커스), `취소`(Esc), `추가`(Enter). 이름이 비어 있으면 `항목 이름을 입력하세요.`를 띄운다.

항목 목록은 정렬하지 않고 추가한 순서대로 둔다.

### 4.9 설정 — 카테고리 관리 (F-CAT) — SCR-03 하단

**구성**: 왼쪽 `지출 분류` 목록(색 사각형 + 이름), `선택한 카테고리 이름 수정` 입력과 `이름 수정` 버튼, `삭제` 버튼. 오른쪽 `카테고리 추가` 영역(이름, 색상 프리셋 드롭다운, HEX 입력과 미리보기 사각형, 48색 팔레트, `추가` 버튼).

카테고리 변경은 버튼을 누르는 즉시 파일에 저장된다(설정 창 닫기와 무관).

| ID | 기능 | 현행 동작 |
|---|---|---|
| F-CAT-01 | 목록 | 모든 카테고리를 §4.10 순서로 보여준다. 창을 열 때와 추가·수정 후 다시 정렬한다. |
| F-CAT-02 | 선택 | 고른 카테고리의 이름이 `이름 수정` 칸에, 색이 **오른쪽 추가 영역의 HEX 칸**에 채워지고 프리셋 선택은 풀린다. |
| F-CAT-03 | 이름 수정 | 선택 필수(`수정할 카테고리를 선택해주세요.`), 이름 필수(`카테고리 이름을 입력해주세요.`), 자기 자신을 뺀 나머지와 이름 중복 금지(대소문자 무시, `이미 존재하는 카테고리입니다.`). 이름을 바꾸고, **HEX 칸 값이 유효하면 색도 함께 바꾼다**(무효면 색은 그대로). 그 뒤 다시 정렬하고 저장한다. |
| F-CAT-04 | 삭제 | 선택 필수(`삭제할 카테고리를 선택해주세요.`). 확인창 `'{이름}' 카테고리를 삭제하시겠습니까?`(제목 `카테고리 삭제`, 예/아니오) 후 지우고 저장한다. **연결된 지출과 메모는 그대로 남는다**(§7 ISSUE-03, 04). |
| F-CAT-05 | 추가 | 이름 필수, 이름 중복 금지(대소문자 무시), 색 유효성(아래). ID는 `기존 최대 ID + 1`(없으면 1). 색은 대문자로 바꿔 저장한다. 추가 후 정렬·저장하고 이름 칸을 비운 뒤 포커스를 준다. |
| F-CAT-06 | 색 프리셋 | 드롭다운에서 고르면 HEX 칸이 그 값으로 바뀐다. 초기 선택은 `빨강`. |
| F-CAT-07 | HEX 직접 입력 | 입력할 때마다 미리보기 사각형을 갱신한다. 해석할 수 없는 값이면 미리보기는 흰색이다. `#` 없이 입력하면(예: `333333`) 미리보기는 흰색이지만 추가는 성공한다(§7 ISSUE-21). 직접 입력해도 프리셋 드롭다운의 이전 선택 표시는 남는다. |
| F-CAT-08 | 팔레트 | 23×23 색 버튼 48개(툴팁은 HEX). 누르면 HEX 칸에 값을 넣고 프리셋 선택을 푼다. 안내 문구: `미리보기에서 색상을 선택하세요.` |

**색 유효성 (추가·수정 공통)**: `#`이 없으면 앞에 붙인다. 길이가 7(`#RRGGBB`) 또는 9(`#AARRGGBB`)이고 색으로 해석될 때만 유효하다. 무효이면 추가 시 `색상을 #RRGGBB 형식으로 입력하거나 팔레트에서 선택해주세요.`를 띄운다.

**색 프리셋 (8종)**

| 이름 | HEX | 정렬상 실제 계열(§4.10) |
|---|---|---|
| 빨강 | `#FCB9BA` | 빨강 (H 359.1°) |
| 주황 | `#FCEBB7` | **노랑** (H 45.2°) |
| 노랑 | `#FBF6A5` | 노랑 (H 56.5°) |
| 초록 | `#B8F6EE` | **파랑** (H 172.3°) |
| 파랑 | `#B7D9FC` | 파랑 (H 210.4°) |
| 보라 | `#DAB6FC` | 보라 (H 270.9°) |
| 분홍 | `#FCBBFB` | 분홍 (H 300.9°) |
| 검정/회색 | `#BDBDBD` | 무채색 |

> '주황'과 '초록' 프리셋은 이름과 다른 계열로 정렬된다. 실행 화면에서도 '초록'으로 만든 카테고리가 '파랑' 카테고리 사이에 섞여 표시됐다(§7 ISSUE-20).

**기본 카테고리**: 없다. 처음 실행하면 카테고리가 0개라 설정에서 먼저 만들어야 지출을 입력할 수 있다(§7 ISSUE-12).

### 4.10 카테고리 정렬 규칙 (F-SORT)

설정 목록, 날짜 칸의 칩, 월간 지출 패널이 같은 규칙을 쓴다.

1차 키는 색 계열 순서, 2차 키는 카테고리 이름 오름차순이다.

색을 RGB(0~1)로 바꾼 뒤 `max`, `min`, `차이 = max - min`, 색상각 `H`(0~360°, HSV 방식)를 구한다. 아래 표를 **위에서부터** 판정한다.

| 순서값 | 계열 | 조건 |
|---|---|---|
| 999 | 색 없음/해석 실패 | 빈 값이거나 파싱 오류 |
| 7 | 무채색(검정/회색/흰색) | `max < 0.15` 또는 `차이 < 0.05` |
| 0 | 빨강 | `H < 15` 또는 `H ≥ 345` |
| 1 | 주황 | `15 ≤ H < 45` |
| 2 | 노랑 | `45 ≤ H < 75` |
| 3 | 초록 | `75 ≤ H < 165` |
| 4 | 파랑 | `165 ≤ H < 255` |
| 5 | 보라 | `255 ≤ H < 300` |
| 6 | 분홍 | `300 ≤ H < 345` |

`#AARRGGBB` 형식은 알파를 무시하고 RGB만 쓴다.

### 5.3 저장 방식과 시점 (현행)

- 저장할 때마다 파일 전체를 다시 읽고, 바꿀 부분만 고친 뒤, 전체를 다시 쓴다.
- 원자적 쓰기: `data.json.tmp`에 먼저 쓰고 `data.json`으로 이름을 바꿔 덮어쓴다.
- 읽기나 쓰기에서 오류가 나면 **조용히 무시**한다. 읽기 실패는 빈 데이터로 처리한다(§7 ISSUE-05, 06).
- 카테고리 목록은 앱 시작 시 한 번 메모리에 올려 공유한다.

## 8. Mac 버전 고려사항 (권고)

### 8.1 기술 구성

웹 기술(Vue.js 또는 React)로 만들어도 된다는 전제에서 정리했다. 본 명세의 기능 정의는 프레임워크와 무관하다.

| 구분 | 권고 | 비고 |
|---|---|---|
| 데스크톱 셸 | **Tauri 2** (1순위) 또는 Electron | Tauri는 macOS 내장 WebKit을 써서 앱이 작고 메모리를 적게 쓴다. Electron은 Chromium을 내장해 렌더링이 일관되지만 앱이 크다. |
| UI | Vue 3 또는 React | 둘 다 가능하다. 달력 그리드와 모달·시트 위주라 특별한 라이브러리 요구는 없다. |
| 상태 관리 | Pinia(Vue) / Zustand 등(React) | 회계월, 시작일, 카테고리 목록을 전역 상태로 둔다. |
| 테스트 | 회계기간 계산(§4.1 표), 정렬 규칙(§4.10), 집계 공식(§4.5)을 단위 테스트로 먼저 고정 | 화면을 다시 만들어도 비즈니스 규칙은 원본과 같아야 한다. |

### 8.2 데이터 저장

- 위치: `~/Library/Application Support/<번들 ID>/data.json` (Tauri의 앱 데이터 디렉터리 API 또는 Electron의 `app.getPath('userData')`)
- 방식: 현행처럼 JSON 파일 하나와 원자적 쓰기를 유지하면 구현이 단순하고 Windows 데이터를 그대로 옮기기 쉽다. 데이터가 많이 늘어날 것으로 보이면 SQLite도 검토한다.
- 반드시 보완할 점: 읽기 실패 시 원본 보관(ISSUE-05), 저장 실패 알림(ISSUE-06), 자동 백업(예: 하루 1회, 최근 N개 보관)
- 브라우저 전용(순수 웹)으로 배포한다면 IndexedDB에 저장하고, 파일 내보내기·가져오기를 필수 기능으로 둔다.

### 8.3 JavaScript 구현 시 주의점

| 항목 | 주의 |
|---|---|
| 날짜 | `Date` 객체는 타임존 때문에 하루가 밀릴 수 있다. 날짜는 `"YYYY-MM-DD"` 문자열로 저장·비교하고, 계산은 date-fns, Day.js, Temporal 같은 도구로 처리한다. |
| 월 계산 | "한 달 더하기"는 일(day)을 1일로 둔 상태에서 해야 한다. 1/31에 1개월을 더하면 JS 기본 동작에서 3월로 넘어갈 수 있다. |
| 금액 | 원화 정수로 다루면 JS `number`로 충분하다(정수 정밀도 약 9천조). 표시는 `Intl.NumberFormat('ko-KR')`. 입력 칸에서 천 단위 콤마를 실시간으로 넣어 주면 좋다. |
| 문자열 비교 | 이름 중복 검사(대소문자 무시)와 이름 정렬은 `localeCompare(…, 'ko')`로 한다. |

### 8.4 Windows 데이터 가져오기 (권고 기능)

기존 사용자가 Windows에서 쌓은 데이터를 옮길 수 있게 `data.json` 가져오기를 제공한다.

| 원본 | Mac 처리 |
|---|---|
| `Date: "2026-11-15T00:00:00"` | 앞 10자리 `2026-11-15`만 날짜로 쓴다(타임존 변환 금지). |
| `Amount` (decimal) | 정수로 반올림한다(원화 정수 정책을 따를 경우). |
| `Categories[].Id` (int) | 새 ID 체계를 쓴다면 원본 ID → 새 ID 매핑표를 만들어 `DayData.CategoryId`와 `CategoryNotes` 키를 함께 바꾼다. |

| `ColorOrder` | 무시한다. |
| `MonthlyAmounts`, `CategoryNotes` | 키 형식(`yyyy-MM`, `yyyy-MM:ID`)을 그대로 쓴다. |
